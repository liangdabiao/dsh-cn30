# 社媒雷达 CN30 —— 中国社媒话题研究

从小红书（种草/攻略/反馈）、抖音（热点/碎片/情绪）、公众号（深度/观点/数据）三大平台搜索近 30 天真实讨论，跨平台对比分析舆情趋势，产出研究报告并内嵌交互式 HTML。

## 平台信号解读

| 平台 | 内容特征 | 关键指标 |
|------|---------|---------|
| 小红书 (xhs) | 种草体验、教程攻略、用户反馈 | 收藏/点赞比高 = 种草信号 |
| 抖音 (dy) | 热点追评、知识碎片、情绪传播 | 分享数 = 传播力 |
| 公众号 (gzh) | 行业深度分析、观点输出、数据报告 | 阅读量 = 关注度，分享 = 认同 |

## 鉴权

需要 RedFox API Key（`ak_` 开头，[红狐 hub](https://redfox.hk/settings/api-keys?source=github) 获取）。优先级：插件配置 > 面板「设置」页 > 环境变量 `REDFOX_API_KEY`。积分不足（3201）时工具会明确提示充值。

## 工作流

### 1. 关键词质量检查

话题过于模糊（"工具"、"方法"）先请用户具体化。对比类需求（"A 和 B 哪个好"）确认对比双方。

### 2. 预研究（可选但推荐）

先做 2-3 个网页搜索提取热词与背景：`小红书 {话题} 热门讨论`、`抖音 {话题} 热门话题`、`{话题} 最新动态`。

### 3. 查询计划

- 相关关键词**合并为一次调用**（英文逗号分隔，如 `"产品经理,AI产品经理"`），每平台最多 5 个词
- 只在话题维度差异极大时才分开调用；默认只搜 1 次
- 时间范围默认 30 天；看近期趋势可设 `days=7`

### 4. 运行引擎

`cn30_search(action="search", keyword="词1,词2", platforms="xhs,dy,gzh", count=50, days=30)` —— 同步秒回，返回每平台 TOP 条目（标题/作者/互动/链接）与统计。数据不够深挖时用 `action="list"`（可按平台过滤、分页、带摘要）。

### 5. 综合分析（Agent 执行）

- **按话题/故事综合，不按平台罗列**
- 多平台交叉验证的结论置信度最高
- 高互动内容权重最高（含真实用户信号）
- 每个叙事段落以粗体标题开头，后跟 ` - ` 和正文

### 6. 存档报告

撰写研究报告 Markdown（引用用 `[名称](url)` 内联链接），然后
`cn30_search(action="report", reportMd="…")` —— 研究报告内嵌到 HTML 报告顶部并落盘。

### 7. 输出（LAW 规则，严格执行）

**徽章（第一行强制）**：`🇨🇳 cn-last30days · {YYYY-MM-DD}`

- **LAW 1** 结尾不要 `Sources:` 块——工具返回的「数据源」页脚是唯一引用
- **LAW 2** 通用查询以 `我的发现：` 开头，禁止章节标题；对比查询例外（标题 `# {A} vs {B}: 跨平台舆情对比`）
- **LAW 3** 不用破折号（`—`/`–`），用 ` - `
- **LAW 4** 引擎页脚逐字附带在输出中（核心发现之后）
- **LAW 5** 每个引用用内联 Markdown 链接（优先作品链接，其次作者主页链接）
- **LAW 6** 不输出原始排名列表，把数据转化为散文洞察
- **LAW 7** 徽章之后、「我的发现」之前必须输出「数据速览」：公众号→小红书→抖音顺序，每平台 TOP5 表格（标题带链接、作者、平台专属指标：公众号 阅读/点赞/转发，小红书 点赞/评论/收藏，抖音 点赞/评论/分享），末尾报数据总量并提示 HTML 报告

**通用查询格式**：徽章 → 数据速览 → `我的发现：`（粗体标题 - 描述 + 来源链接）→ 核心发现 1-3 条 → 页脚 → 「我是 {话题} 的专家，可以帮你…」邀请。

**对比查询格式**：徽章 → `# {A} vs {B}: 跨平台舆情对比` → 一句话结论 → 双方优劣势（带来源）→ 对比表格（小红书讨论/抖音热度/公众号评价/适合谁）→ 「选 A 如果…/选 B 如果…」→ 页脚。

## 错误处理

| 情况 | 处理方式 |
|------|---------|
| 未配置 RedFox API Key | 引导用户到面板「社媒雷达 CN30 → 设置」填写 |
| 积分不足（3201） | 工具会提示充值地址，如实转述，不要重试轰炸 |
| 某平台 0 结果 | 如实说明（关键词可能太生僻），建议换口语化关键词，别编造条目 |
| 部分平台失败 | 继续分析成功平台的数据，失败项如实标注 |
| 小红书链接打不开 | 平台风控所致，提示用户复制标题去小红书搜索（报告里已有此提示） |

## 在 DSH 插件里使用

- `cn30_search` 工具负责搜索/持久化/HTML 报告；话题综合研究与输出由你完成
- 历史记录：`history` 列出（新→旧），对旧记录补研究报告传 `searchId` + `reportMd`；缺省作用于最新记录
- 面板可直接搜索/看结果/直出纯数据版报告；与对话流程共用同一份数据
